# ML: поиск товаров под сумму кредита

Модуль `smart_credit_ml.product_search` ищет в интернете товары по ключевым словам. В подборку попадают только те, что укладываются в сумму кредита. Пример: предприниматель берёт 1,5 млн ₽ на оборудование и видит реальные предложения магазинов, которые можно купить на эти деньги.

## Как устроено

```
ключевые слова + сумма кредита
        │
        ▼
 Qwen 3.5 (Ollama) ── составляет 1–3 поисковых запроса по строгим правилам;
        │              запросы, нарушившие правила, код отбрасывает
        ▼
 SearXNG ── настоящие ссылки и сниппеты из поисковиков
        │  (дубликаты и utm-метки убираются, не больше 3 ссылок с одного сайта)
        ▼
 загрузка страниц ── schema.org Product / microdata / og:price: цена из разметки
        │  (только публичные адреса, редиректы проверяются, до 1,5 МБ на страницу)
        ▼
 каталоги ── страница со списком товаров (ItemList) заменяется карточками из списка,
        │    у каждой своя ссылка и цена; сама ссылка на каталог в подборку не попадает
        ▼
 Qwen 3.5 ── обычные страницы: полный разбор по 4 за вызов (карточка ли это товара,
        │    подходит ли он, какая цена указана);
        │    карточки из каталогов: лёгкая проверка по 20 за вызов, только по названию
        ▼
 дубли ── один товар одного магазина остаётся один раз, с меньшей ценой
        │
        ▼
 фильтр: цена ≤ суммы кредита → offers; дороже → overBudget (до 3 штук для справки)
```

Почему не «попросить модель найти ссылки». Языковая модель не ходит в интернет. Ссылки, которые она пишет по памяти, выдуманы или давно мертвы. Поэтому:

- **URL пишет только поисковик.** Модель отвечает номером результата, а ссылка берётся из этого результата. Номер, которого не было в выдаче, отбрасывается.
- **Цену из разметки страницы модель не трогает.** Если разметки нет, цена, названная моделью, принимается только когда это же число есть в тексте страницы или в сниппете. Иначе предложение уходит в `stats.noPrice`.
- **Валюта.** Цена из разметки в другой валюте не считается рублями.
- **Каталоги.** Поисковики на запрос «купить … цена» отдают в основном страницы категорий. Страница считается каталогом, если в её разметке есть ItemList с несколькими товарами, несколько разных товаров на верхнем уровне или несколько блоков microdata Product. У каталога нет своей цены: из него берутся карточки (не больше 10 с одной страницы и 40 всего), у которых есть своя ссылка и цена. Ссылка карточки должна вести на тот же сайт. Карточки без ссылки отбрасываются, ссылка на сам каталог не выдаётся никогда, даже если модель сочтёт его товаром.
- **Лёгкая проверка карточек.** У карточки из каталога название и цена уже известны из разметки, поэтому полный разбор страницы ей не нужен. Модель получает только названия, до 20 за один вызов (`card_batch`), и отвечает, тот ли это тип товара (а не аксессуар, комплектующая или другой товар), с оценкой релевантности от 1 до 5. Обычные страницы по-прежнему разбираются полностью, по 4 за вызов (`judge_batch`). В живом тесте это сократило поиск по одной категории с 5 минут до 2.
- **Названия из разметки.** Если у страницы или карточки есть название товара в разметке schema.org, в подборку идёт оно, а не название от модели. Модель пересказывает названия и может исказить характеристики. Её название используется только для страниц без разметки.
- **Правила поисковых запросов.** Модель обязана сохранять тип товара из ключевых слов: для «компьютер» нельзя искать «ноутбук», «моноблок» или «компьютерную технику». Запрещено добавлять уточнения, которых нет в ключевых словах («игровой», «для работы», бренды, модели). Цена допустима только как верхняя граница «до N рублей», без нижней границы и диапазонов. Слова о способе оплаты («кредит», «рассрочка», «заём», «лизинг») тоже запрещены: такие запросы приводят на страницы банков вместо магазинов. Код дублирует эти правила, потому что маленькая модель их иногда нарушает. Запрос отбрасывается, если в нём нет всех ключевых слов (сравнение по основе слова), если есть «от N» или диапазон «N–M», или если встречается слово на «кредит», «рассроч», «займ/заём», «лизинг», «ипотек». Отброшенные запросы перечисляются в `warnings`. Если модель не предложила ни одного годного запроса, используется шаблон «ключевые слова + купить цена».
- **Дубли.** Одна и та же ссылка, найденная в двух каталогах или и в поиске, и в каталоге, берётся один раз. Один и тот же товар одного магазина под разными ссылками (совпадает название без учёта регистра, пунктуации и «ё») остаётся один раз, с меньшей ценой. Одинаковые товары в разных магазинах — разные предложения.
- **Источник цены** виден в поле `priceSource`: `structured` (разметка страницы товара), `catalog` (разметка карточки в каталоге), `page_text` (текст страницы, проверено), `snippet` (сниппет поисковика, проверено).
- **Без модели.** Если Ollama недоступна, модуль ищет по самим ключевым словам и оставляет только страницы и карточки с ценой в разметке schema.org, с релевантностью 1. Об этом сообщает `warnings`.
- **Режим размышления выключен** (`think: false`). На GTX 1050 Ti с размышлением разбор одной карточки занял 83 с, без него 5,7 с, и ответ был тот же.

Модель — Qwen 3.5 с открытыми весами, этого требует кейс. Поисковик — SearXNG в своём контейнере. Платных API нет.

## Запуск

Всё сразу, из корня репозитория:

```bash
docker compose up --build ml
```

При первом старте `ollama-pull` скачивает модель (`qwen3.5:4b`, около 3 ГБ) в том `ollama-data`. Модель меняется переменной `ML_LLM_MODEL` в корневом `.env`.

Проверка:

```bash
curl -X POST http://localhost:8000/product-search -H "Content-Type: application/json" -d "{\"keywords\": \"холодильная витрина\", \"budgetRub\": 500000, \"purpose\": \"Покупка оборудования\"}"
```

Swagger: http://localhost:8000/docs

Локально без Docker для ML-сервиса (Ollama и SearXNG при этом запущены, например через compose):

```bash
cd src/ml
python -m venv .venv
.venv/Scripts/python -m pip install --require-hashes -r requirements-test.lock
.venv/Scripts/python -m pip install --no-deps -e .
.venv/Scripts/smart-credit-products "холодильная витрина" 500000 --purpose "оборудование"
.venv/Scripts/uvicorn smart_credit_ml.api:app --port 8000
```

Зависимости ставятся двумя командами: pip не разрешает смешивать пакеты с хешами и пакет без хеша (`-e .`) в одном вызове.

## Зависимости

Версии закреплены lock-файлами с хешами пакетов. Lock-файлы разрешены для Python 3.12 и сразу для Windows и Linux:

| Файл | Что внутри | Где используется |
|---|---|---|
| `requirements.lock` | зависимости сервиса | `Dockerfile`: `pip install --require-hashes -r requirements.lock` |
| `requirements-test.lock` | то же плюс `pytest` | локальная разработка и тесты |

В `pyproject.toml` указаны допустимые диапазоны версий, а в lock-файлах — точные версии, которые ставятся на самом деле. Образ не устанавливает пакет через pip: код лежит в `/app/src` и подключается через `PYTHONPATH`, поэтому в образ не попадает ничего, кроме закреплённых пакетов.

После изменения зависимостей в `pyproject.toml` lock-файлы пересобираются через [uv](https://docs.astral.sh/uv/):

```bash
uv pip compile pyproject.toml --universal --python-version 3.12 --generate-hashes --no-header -o requirements.lock
```

```bash
uv pip compile pyproject.toml --extra test --universal --python-version 3.12 --generate-hashes --no-header -o requirements-test.lock
```

## API

Сервис слушает порт **8000**: это адрес `Ml:BaseUrl` в `src/backend/appsettings.json`. В Compose бэкенду передаётся `Ml__BaseUrl=http://ml:8000`.

### `POST /` — передача заявки от бэкенда

Этот запрос шлёт `PurposeHandoff.cs` на этапах проверки по реестрам и скоринга:

```json
{
  "applicationId": 10,
  "amount": 1500000,
  "purpose": "зерноуборочный комбайн",
  "category": {
    "purpose": "зерноуборочный комбайн",
    "matches": [
      { "code": "grain-harvester", "title": "Зерноуборочный комбайн", "keywords": ["зерноуборочн комбайн", "зерноуборочн"] }
    ]
  }
}
```

`purpose` — текст цели кредита из заявки. Поле необязательное: берётся верхнеуровневое `purpose`, а если его нет, то `category.purpose`. Без него сервис работает как раньше, только по названиям категорий. Цель передаётся модели при составлении запросов, при полном разборе страниц и при лёгкой проверке карточек. Это нужно для неоднозначных названий: у слова «комбайн» есть и кухонный, и зерноуборочный смысл, и без цели модель не может их различить.

Бэкенд ждёт ответ 3 секунды и читает только код ответа, а поиск идёт минуты. Поэтому сервис сразу отвечает `202 Accepted` с `{"applicationId", "status", "results"}` и ставит задание в очередь. Фоновый воркер выполняет задания по одному: Ollama всё равно держит одну модель. По каждой категории, не больше трёх (`ML_HANDOFF_MAX_CATEGORIES`), он ищет её название (`title`) с бюджетом, равным сумме кредита.

Статусы задания:

| `status` | |
|---|---|
| `queued` | принято, ждёт воркера |
| `running` | идёт поиск |
| `done` | поиск прошёл хотя бы по одной категории |
| `failed` | ни одна категория не нашлась: поисковик недоступен или упал поиск |
| `no_categories` | бэкенд не распознал в цели ни одного товара, искать нечего |

**Повторы.** Бэкенд повторяет передачу, если не получил 2xx. Задание в статусе `queued`, `running` или `done` при повторе не перезапускается. Задание в статусе `failed` запускается заново. Задания, оставшиеся `queued`/`running` после остановки сервиса, при старте снова ставятся в очередь.

Задания хранятся в базе `ml`, в таблице `ml.goods_searches` (`sql/002_goods_searches.sql`). Сервис создаёт её при старте, если таблицы нет, а в уже существующую таблицу добавляет колонку `purpose`. `ML_GOODS_STORE=memory` держит задания в памяти процесса, это удобно для запуска без Postgres.

### `GET /applications/{id}/goods` — результат поиска по заявке

Ответ: `applicationId`, `amount`, `purpose` (цель кредита или `null`), `status`, `categories` (как прислал бэкенд), `error`, `updatedAt` и `results[]`. В каждом элементе `results`: `code`, `title`, `keywords` и либо `search` (ответ в формате `/product-search`), либо `error`. Для неизвестной заявки ответ 404.

### `POST /product-search` — один поиск сразу

| Поле | Тип | |
|---|---|---|
| `keywords` | string, 2–200 | что купить |
| `budgetRub` | number > 0 | сумма кредита |
| `purpose` | string? | цель кредита, помогает составить запросы |
| `maxResults` | int 1–30, по умолчанию 10 | |

Ответ: `queries`, `offers[]` (`name`, `url`, `domain`, `priceRub`, `priceSource`, `relevance` 1–5, `reason`, `query`), `overBudget[]`, `stats` (`candidates`, `fetched`, `catalogs`, `listed`, `duplicates`, `notOffer`, `noPrice`, `overBudget`), `warnings[]`, `searchUnavailable` (ни один запрос к поисковику не выполнился). Подборка отсортирована по релевантности, при равной — по цене. У карточек из каталога в `reason` указан сайт каталога: «Карточка из каталога market.yandex.ru: название и цена из разметки».

## Тесты

```bash
.venv/Scripts/python -m pytest
```

Тесты (35 штук) подменяют поисковик, загрузку страниц и модель фейками, поэтому интернет и Ollama для них не нужны. Они проверяют разбор разметки и каталогов, защиту от выдуманных ссылок и цен, удаление дублей, правила запросов, лёгкую проверку карточек, передачу цели кредита модели и приём заявки от бэкенда в теле запроса, которое формирует `PurposeHandoff.cs`, с полем `purpose` и без него.

## Ограничения

- Крупные маркетплейсы (Ozon, Wildberries, DNS) часто не отдают страницу боту. По ним цена берётся из сниппета поисковика, если она там есть.
- Многие магазины отдают каталоги без разметки товаров (в живом тесте — pc-arena, kns.ru, dinks-comp). Модель правильно отмечает их как каталоги, но товары из них не извлекаются: ссылки на карточки она бы выдумала. В живых тестах все предложения пришли с Яндекс Маркета.
- `qwen3.5:4b` почти всем товарам ставит релевантность 5, поэтому на практике подборка сортируется по цене.
- Цены в выдаче меняются. Результат по заявке сохраняется один раз и сам не обновляется. Поиск по одной категории на `qwen3.5:4b` с GTX 1050 Ti занимает около 2 минут.
- Бэкенд узнаёт категорию по подстроке в цели кредита, поэтому возможны ложные совпадения: «компьютер» находится и в «компьютерный стол», «зерно» — в «зерноуборочный». Цель кредита в поле `purpose` помогает модели отсеять неподходящие товары, но лишняя категория всё равно будет искаться.
